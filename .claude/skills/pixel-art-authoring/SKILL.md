# Pixel-art authoring

Art here is **generated by committed code**, not hand-drawn binaries.
`tools/gen_assets.py` is the source of truth; `assets/*.png` are build
outputs that happen to be committed. That means any sprite can be
re-derived, diffed, and tweaked by editing a few numbers — and nobody
is ever blocked waiting on a binary asset they cannot open.

## Rules that keep it looking like pixel art

1. **Never anti-alias.** Set pixels or fill exact integer rects. PIL's
   `ellipse`/`arc` produce soft edges — draw curves by plotting pixels
   or accept a blocky approximation, which is the correct look anyway.
2. **Never scale in the generator.** Author at the native size in
   `docs/art-direction.md`; the game upscales by an integer factor with
   nearest-neighbour sampling. Scaling in PIL (or a non-integer factor
   at runtime) is what produces the blurry half-pixel mush that
   instantly reads as amateur.
3. **Palette discipline.** Define the palette once as a name -> RGB
   dict and reference it by name. Every opaque pixel must be a palette
   entry — assert this in the generator, do not trust yourself.
4. **Shade with the _dark/_light pairs.** A 1px darker bottom edge and
   1px lighter top edge turns a rectangle into an object. Flat fills
   are exactly what "programmer art" means.
5. **Determinism.** No unseeded randomness. Re-running must produce
   byte-identical files or every asset change becomes an unreviewable
   diff.

## Readability at tiny sizes

A 24x32 character has no room for detail: big head, 2px eyes, no
mouth, silhouette over features. Test readability by viewing at 1x —
if you cannot tell what it is without upscaling, simplify rather than
adding pixels. For animation frames, change ONLY the pixels that move
(arms for typing); moving the whole body reads as jitter, not motion.

## Self-check before handing off

```bash
python3 tools/gen_assets.py
# then render the real game and judge it, do not judge the PNGs alone:
source ~/.cargo/devcompanion-env.sh
SHOTCAP_OUT=/tmp/shots SHOTCAP_EXIT_SECS=6 cargo run -p shotcap
python3 scripts/visual-check.py /tmp/shots/shot_5s.png \
  "Describe this game screenshot: scene, character, art style, palette. Be critical — if it looks like placeholder rectangles, say so."
```

Quote the vision model's verdict in your handoff. A sprite that looks
fine in isolation can still disappear against the background or sit at
the wrong scale once composed — only the composed screenshot tells you
that.
