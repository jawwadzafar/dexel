# 0004 — Procedural pixel art; the generator is the source format

Status: accepted (v0.2)

## Context
The game needs real pixel art (Steam-tag register: Pixel Graphics, Cozy,
Minimalist). Hand-drawn binaries are unreviewable and undiffable; SVG was
asked about explicitly.

## Decision
All sprites are generated by `tools/gen_assets.py` (Python + PIL) from an
18-colour fixed palette defined once. `assets/*.png` are committed build
artifacts. Deterministic: byte-identical re-runs; the generator asserts every
opaque pixel is a palette colour. No anti-aliasing, no resize except NEAREST,
authored at native size and integer-upscaled at runtime
(`ImagePlugin::default_nearest()`).

## Why not SVG
Bevy has no native SVG loading (upstream #1139); `bevy_svg` tessellates to
meshes, and vector rasterisation anti-aliases — which destroys the pixel-art
look by design. Recolouring via the single palette dict is strictly better
than editing fills across 15 SVG files.

## Consequences
- Any sprite is re-derivable and reviewable as a code diff.
- Art iteration is scriptable by agents, which is how this project works.
- The spec (`docs/art-direction.md`) is normative; where its prose and its
  layer list disagree, the prose wins (that contradiction shipped once).
