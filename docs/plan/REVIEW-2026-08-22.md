## BLOCKING

### B-1 — Unsigned `state.json` grandfather path mints anything, with no key

`app/internal/store/store.go:999` only checks the MAC when
`d.Schema >= 5`; `app/internal/store/db.go:537,546` then treats a
MAC-less save as trusted, stamps it `CurrentSchema`, and **signs it**:

```go
// store.go:999
if d.Schema >= 5 && !verifyMAC(d) { ... quarantine ... }
// db.go:537
mac := d.Mac
if mac == "" { d.Schema = CurrentSchema }
payload := canonicalBody(d)
if mac == "" { mac = computeMACBytes(payload) }   // ← laundered
```

`LoadAll` (`store.go:895`) takes the JSON-import branch whenever
`state.db` does not exist. So the attack is *delete one file, write
another* — no HMAC key, no tooling, no understanding of the scheme:

```
$ rm ~/.config/dexel/state.db
$ cat > ~/.config/dexel/state.json <<'EOF'
{"schema":4,"devCash":999999999,"xp":424242,
 "ownedItems":["chair_exec","kb_split","mouse_trackball","wall_shelf","buddy_cat"],
 "sprint":{"index":5,"unitsDone":0}}
EOF
$ dexel serve -addr 127.0.0.1:0 -provider fake
loaded save from .../state.db (dev_cash=999999999, sessions=0)
```

Verified end to end against a temp home. Reading the resulting DB back:
`schema col 6`, `devCash 999999999`, `owned [... buddy_cat, chair_exec,
kb_split, mouse_trackball, wall_shelf ...]`, a **valid** MAC. A second
run reloads it clean. `state.json` is renamed `.imported`, but renaming it
back (or writing a fresh one) repeats the mint indefinitely.

Why this is blocking rather than the accepted non-goal: ADR 0014 /
SEC-1 §3 accept "a determined user who reads integrity.go and recomputes
the MAC", and explicitly claim the scheme stops casual save-file editing
**"completely"** (`integrity.go:20-25`). This path *is* casual editing —
it is strictly easier than editing the old `state.json` was, because you
never have to defeat a MAC at all. The claim in the source comment is
currently false.

Notes for whoever fixes it: the grandfather window exists for genuine
pre-SEC-1 saves, which are all `schema ≤ 4` `state.json` files created
before today. Options that keep that promise without keeping the hole:
require the imported file to be `schema == 5` **with** a valid MAC and
treat `schema ≤ 4` as import-once-then-never (a marker inside the signed
DB, not a filename), and/or clamp an unsigned import to a plausible
ceiling instead of trusting `devCash` verbatim.

### B-2 — The legacy-Rust import is unsigned, unbounded and repeatable

`app/main.go:1179-1196` falls through to `store.LoadLegacy` /
`store.ImportLegacy` on the genuine "no save" path, and
`app/internal/store/legacy.go:151` takes the wallet verbatim
(`devCash := legacy.Wallet`, a `uint64`), plus every item the upgrade
table can grant.

```
$ rm ~/.config/dexel/state.db          # or start clean
$ mkdir -p ~/.local/share/dev-companion
$ echo '{"wallet":18446744073709551615,"xp":9999,"level":99,
         "upgrades":{"chair":9,"keyboard":9,"mouse":9,"pet":9,
                     "wall":9,"desk_decor":9,"monitor":9}}' \
      > ~/.local/share/dev-companion/save.json
$ dexel serve -addr 127.0.0.1:0 -provider fake
imported legacy save from .../save.json (dev_cash=18446744073709551615,
  owned=[... buddy_cat buddy_duck chair_exec chair_racer kb_mech kb_split
  mouse_gaming mouse_trackball plant_succulent wall_poster wall_shelf])
```

Verified (with `HOME` pointed at a temp dir). Note the tier clamp
(`useTier > maxTier`) works — the mint comes from `wallet`, which has no
clamp at all. The legacy file is never consumed or marked, so deleting
`state.db` re-runs the grant every time.

SEC-1's own reasoning names this exact danger — `store.go:141` and
`main.go:1067-1075` argue at length that a tampered save must not be
mistaken for "no save" *because the legacy path grants items and refunds
Dev Cash*. That reasoning closed the indirect route and left the direct
one (actually have no save, and forge the legacy file) untouched.

### B-3 — A single failed `AppendSession` destroys the save on the next start

Three facts compose into total data loss for an honest user:

1. `game.finishSession` appends the record to `g.sessionLog` **before**
   anything is persisted (`session.go:276-290`), and
   `popEndedSession`'s failure branch (`main.go:723-726`) logs, flashes
   "could not save session", and **returns with the record still in the
   in-memory log** — `g.SetSessionLogHead(newHead)` at `main.go:727` is
   skipped, correctly, but nothing rolls the record back.
2. The next `StartSession` derives its id from that in-memory log:
   `id: len(g.sessionLog) + 1` (`session.go:212`). So after one failed
   append, every future id is **one higher than the DB's next row**.
3. `AppendSession` inserts that id verbatim (`db.go:501`, a plain
   `INSERT`), and the loader treats a gap as tampering:
   `db.go:403 if id != want { ... ErrTampered ... }` → `failClosed` →
   the whole `state.db` is quarantined and the user starts from zero.

I proved step 3's consequence directly. Using the published key I forged
a well-formed log with rows `1` and `3` (row 3 correctly chained onto row
1 — exactly the shape step 2 produces) and a matching signed head:

```
save integrity check failed; starting a fresh economy:
  sessions row id 3 out of sequence (want 2);
  original preserved untouched at .../state.db.invalid
```

So: one transient write failure (disk full, an `ENOSPC` on the state
partition, a locked DB — see SF-1) turns into "your entire economy is
gone and the app says your save was tampered with". The failure is also
*silent at the time*: the user sees one "could not save session" toast
and keeps playing, and the bomb goes off on the next launch.

Cheapest fix: drop the record from `g.sessionLog` when the append fails
(or derive the next id from the persisted head/`MAX(id)` rather than from
the in-memory slice length), and consider `INSERT` → an explicit
"expected next id" check so a collision is a clean error instead of a
poisoned sequence.

## SHOULD-FIX

### SF-1 — `dexel serve` shares the state dir with a live runtime, unlocked

`main.go:169-198` takes `runtime.lock` **only** for `modeRuntime`;
`modeServe`/`modeLegacy` deliberately skip it so "a developer can run a
scratch instance next to a real one exactly as they can today"
(ARCHITECTURE.md Decision 7). But `serve` also resolves the *same*
`store.DefaultPath()`, so two processes now own one `state.db`:

- `store.Save` (`store.go:789`) is a whole-row upsert with no read-back
  and no version check — last writer wins, silently.
- Both processes hold independent in-memory `sessionLog`s, so their
  session ids collide; `db.go:501`'s plain `INSERT` then fails with a
  UNIQUE violation, which is exactly the trigger for **B-3**.

Before P2 the cost of this affordance was "two instances clobber each
other's autosaves". After P2 it is "two instances can permanently
quarantine the save". Either scope `serve` to its own state dir by
default, or make it refuse to start when a runtime holds the lock.

### SF-3 — `go test -race` will fail on the runner even once CI starts

`build.yml:89`, `build.yml:145` and `release.yml:106` all guard with
`if ! command -v cc`, then fall back to `|| echo "no sudo — relying on an
existing cc/zig toolchain"`. On this machine `cc` **does** exist — it is a
zig shim at `~/.local/bin/cc` — so the install is skipped. Go, however,
invokes `gcc` unless `CC` is set, and no workflow sets `CC`:

```
$ CGO_ENABLED=1 go test -race ./...
# runtime/cgo
cgo: C compiler "gcc" not found: exec: "gcc": executable file not found in $PATH
FAIL ... (all packages)
$ CGO_ENABLED=1 CC=cc go test -race ./internal/paths/     # ok
```

`sudo -n true` on this box reports "interactive authentication is
required", so the `apt-get` fallback cannot rescue it either. Fix by
exporting `CC=cc` (and `CXX`) in the job env, or by probing for `gcc`
specifically.

### SF-4 — `build-release.sh` is not runnable on the macOS path it claims

`scripts/build-release.sh:97-99` adds `darwin/arm64` to the default target
list when `GOHOSTOS=darwin`, and the header sells the script as "runnable
and testable on a laptop with no CI involved at all". But:

- `scripts/build-release.sh:220` calls `sha256sum`, which does not exist
  on macOS (`shasum -a 256` does). The failure lands *after* every target
  has been built and archived.
- `scripts/build-release.sh:199` calls `zip` for the two Windows targets
  with no `command -v zip` precheck; the Linux runner happens to have it,
  a fresh runner may not, and again the failure is late.

The drift/completeness checks themselves are correct and do reference the
renamed files (`app/public/index.html`, `app/public/js/dexel.js`,
`app/assets/room_back.png` — `:138-151`).

### SF-5 — Linux `$XDG_CONFIG_HOME` installs are silently orphaned by PR-1

Pre-PR-1, `store.DefaultPath()` hardcoded `~/.config/dexel`. PR-1's
`stateDirFor` (`paths.go:95`) now honours `$XDG_CONFIG_HOME`, and
`paths_other.go`'s `relocateHook` is a **deliberate** no-op whose comment
asserts "Linux never takes this branch — Linux's StateDir already IS
`~/.config/dexel` (or `$XDG_CONFIG_HOME/dexel`), so there is nothing to
relocate FROM."

That "or" is exactly the gap. For a user with `XDG_CONFIG_HOME` set (a
common dotfiles setup), the new dir is *not* the old one, and Linux is the
one platform with no relocation. The stated compat rule ("existing
`~/.config/dexel` installs truly untouched") holds only for
`XDG_CONFIG_HOME`-unset machines. Cheapest fix: give Linux the same
`relocateLegacy(~/.config/dexel, newDir)` hook the other two OSes have —
it is already a no-op when the two paths are equal (`paths.go:193`).

### SF-6 — Relocation misses a `state.json`-only install

`relocateLegacy` (`paths.go:201`) triggers **only** if
`legacyDir/state.db` exists, and `relocationFiles` (`paths.go:57-64`)
lists `state.json.imported` but **not** `state.json`. A macOS/Windows
install created by an early-today build (post-rename, pre-DB-1) has
`~/.config/dexel/state.json` and no `state.db` → no relocation → the new
platform dir is empty → fresh start, with the real save orphaned where
nothing will ever look again. Narrow (same-day builds only) but it is
precisely the compat rule PR-1 exists to honour, and the fix is two lines:
add `state.json` to `relocationFiles` and trigger on either file.
`paths_test.go:242` covers `state.json.imported` and not this case.

### SF-7 — `DEXEL_HOME` does not isolate the legacy-import source

`store.LegacyPath()` (`legacy.go:19`) resolves from `os.UserHomeDir()`
and never consults `paths`/`DEXEL_HOME`. I hit this by accident while
attacking a throwaway home:

```
$ DEXEL_HOME=/tmp/.../wshome dexel serve ...
imported legacy save from /home/darkmirror/.local/share/dev-companion/save.json (dev_cash=65, ...)
```

A run that is supposed to be sandboxed silently ingested the real user's
legacy save. Read-only, so nothing was damaged — but it means
`DEXEL_HOME` is not a sandbox, tests/demos can pick up real user data,
and B-2's repro surface is wider than the state dir suggests.

## NITs

- **N-1 — repeated quarantine destroys the earlier evidence.** `quarantine`
  (`db.go:103-104`) renames to a fixed `path+suffix`, so a second tamper
  overwrites `state.db.invalid`. The message still promises "original
  preserved untouched … NOT deleted". Verified: two tampers, still exactly
  one `.invalid`. A counter/timestamp suffix would make the promise true.
- **N-2 — a crash artifact is reported as tampering.** A zero-byte
  `state.db`, or a valid DB with no `state` table (what a kill between
  `openDB` and the first commit leaves), produces
  `save integrity check failed: state table missing or unreadable`
  (`db.go:299`) and a `.invalid` quarantine. Both verified. Accusing the
  user of tampering for a torn first write is worth its own message.
- **N-3 — state-dir permissions depend on the entry point.**
  `lifecycle.AcquireLock`/`WriteRuntime` create it `0700`
  (`lock.go:47`, `runtimefile.go:133`); `store.openDB` and
  `writeFileAtomically` create it `0755` (`db.go:137`, `store.go:817`), and
  `MkdirAll` never tightens an existing dir. So `dexel start` → `0700`,
  `dexel serve` → `0755`, with `state.db` and `config.json` at `0644` —
  on a shared box another local user can read the counters and the
  dexel/session names. (`runtime.json`, `runtime.lock`, `runtime.log` are
  `0600` and `logs/` is `0700` — verified, see C-9.)
- **N-4 — `dexel -h` / `--help` print the *server's* flags**, not the
  command list (`cli.go:124`, shape-not-membership). Intentional and
  documented, but these are the two flags every user tries first; the
  product CLI's help is unreachable except via the exact word `help`.
- **N-5 — a losing `dexel start` still claims it started the runtime.**
  Five parallel starts all printed `dexel started (pid 1792110)` — four of
  them for a process they did not spawn (the pre-spawn `Discover` missed
  the race, then `waitReady` found the winner). Harmless, mildly dishonest.
- **N-6 — no in-app rename.** `SET_NAME` is sent only by
  `onboarding-modal.ts` (`:294`, `:322`), and onboarding opens only when
  the server says `onboarding` (fresh install, no name). Esc closes the
  modal and **commits the name `dexel`** (`onboarding-modal.ts`'s `close`
  handler). Same dead end if `persistConfig` fails: the name lives in
  memory, the error toast is honest, and the next boot has no save-less
  path back to the modal. Hand-editing `config.json` is the only escape —
  legitimate by design, undiscoverable in-app.
- **N-7 — session duration is wall clock, including time the app was not
  running.** `durationSecondsBetween(startedAt, endAt)`
  (`session.go:104`) spans process downtime and laptop sleep. The idle
  auto-end covers gaps ≥ 2 h *and only when the provider is sighted*
  (`SeesGlobalInput`, `session.go:148` — correctly refusing to claim idle
  from a blind provider). A 30-minute app restart mid-session is
  therefore counted as session time. Honest-ish, but "1h 24m together"
  can include an hour where dexel was not running.
- **N-8 — bidi/format characters survive name normalisation.**
  `normalizeUserText` (`identity.go:68`) strips `unicode.IsControl` (Cc)
  only, so U+202E RTL-override, ZWJ, ZWSP pass into the titlebar and
  `config.json`. Verified over the wire. Cosmetic and self-inflicted; no
  XSS (see C-7).
- **N-9 — the source map ships in the binary.** `//go:embed all:public`
  (`embed.go:41`) includes `js/dexel.js.map` (226 KB) and serves it. Fine
  for an Apache-2.0 project, but it is a third of the embedded frontend.
- **N-10 — subcommands ignore extra positional args** (`dexel status extra`,
  `dexel version extra` both succeed silently).

## CLEAN-CONFIRMED (attacked, could not break)

- **C-1 — state-payload tamper → fail-closed.** Edited `devCash` in the
  `state.payload` BLOB with `sqlite3` (Python), left the MAC: quarantined
  to `state.db.invalid`, original preserved, fresh economy, no partial
  load. The claimed gate is real.
- **C-2 — the chained session log survived all six attacks I devised.**
  Starting from a fully valid forged 2-row log: delete the last row →
  *head mismatch*; replay the signed state payload into a session row →
  *chain broken* (domain separation works); swap two rows' payloads →
  *chain broken at row 1*; duplicate a row as id 3 → *chain broken*; drop
  the `sessions` table with a non-empty head → *table missing but head
  signed*; edit only the `ended_at` mirror → *mirror disagrees with
  payload.endedAt*. All six quarantined, all six named precisely.
- **C-3 — a valid DB with rows 1 and 3 is rejected** (`out of sequence`) —
  which is what makes B-3 destructive, but the *detection* itself is
  correct and strict.
- **C-4 — WebSocket origin enforcement.** `Origin: http://evil.example` →
  rejected at the handshake; `Origin: null` → rejected; `http://127.0.0.1:1`
  (right host, wrong port) → rejected; `http://localhost:18099` → accepted.
  `wsOriginPatterns` derives the patterns from the **resolved** port and
  never from a non-loopback bind host (`main.go:794-799`). An absent Origin
  is accepted by the library — documented posture, and the `-insecure-origin`
  / `-allow-origin` escapes are both opt-in and off by default.
- **C-5 — `-allow-origin` parsing** (`main.go:762`, `originList.Set`)
  splits on commas, trims, drops empties, appends across repeats — no
  wildcard path, and `wsExtraOriginPatterns` extracts a host from a full
  origin URL.
- **C-6 — 18 malformed/hostile WS payloads: no crash, no panic, no
  partial state.** Truncated JSON, an empty frame, `action: null`,
  `action: 1`, `itemId` as an object, 200-deep nesting → single
  `flash{kind:"error", text:"malformed message"}` and the connection (and
  its store-open hold) stays alive, exactly as `handlers.go:80-98`
  claims. A 1 MB `name` just closes that one connection (library read
  limit). ANSI/ESC bytes are stripped from names; whitespace-only is
  rejected; unknown item ids, unowned equips, `SESSION_STOP` with no
  session and a double `SESSION_START` all produce clean error flashes;
  50× `STORE_OPEN` from one connection is idempotent (set-keyed by
  connID). The server was still healthy afterwards.
- **C-7 — no XSS surface.** Every dynamic string goes through
  `textContent`; the only `innerHTML` uses in `app/frontend/src` are
  `= ''` clears. A name of `<img src=x onerror=alert(1)>` renders as text.
- **C-8 — ADR 0010 honesty in the P2 UI.** The titlebar pill and the live
  modal render the **server's** `elapsedSeconds`
  (`chrome.ts:75`, `sessions-modal.ts:154`); the only `setInterval`s in
  the frontend are the 5 fps sprite animation and the cursor blink, both
  gated on server-sent `activeState`. Nothing fabricates activity, idle,
  mood or elapsed time; a dropped socket freezes the clock rather than
  inventing seconds.
- **C-9 — runtime file hygiene.** Verified on disk:
  `runtime.json 0600`, `runtime.lock 0600`, `logs/ 0700`,
  `runtime.log 0600`; the token is 32 bytes of `crypto/rand`, hex, minted
  per start (`runtimefile.go:32`), written tmp→fsync→chmod 0600→rename.
- **C-10 — the runtime log is content-free.** A full boot log contains
  paths, version/commit, the provider description, save/onboarding
  decisions — no keystroke content, no window titles, no app names. (The
  dexel's own *name* is logged at boot, `main.go:301` — user-authored free
  text, in a 0600 file, which is the one place ADR 0014 puts free text
  anyway.) Structural content-free allow-lists were extended to the new
  P2 types (`store/content_free_test.go:40,269-320`).
- **C-11 — single-instance and lifecycle behaviour.** 5 parallel
  `dexel start` → exactly one runtime, four clean "another process holds
  runtime.lock" exits; `kill -9` → `status` detects and cleans the stale
  `runtime.json` via a real HTTP round-trip; `stop` is idempotent, saves
  on the way out (`state.db` appeared), and removes `runtime.json`;
  `dexel <typo>` exits 2 with usage; `dexel ""` is an unknown command,
  not a server start.
- **C-12 — build and test hygiene.** `go vet ./...` clean;
  `go test ./...` clean (8 packages); `go test -race ./...` clean with
  `CC=cc`; `tsc --noEmit` clean; a fresh `esbuild` build of
  `app/frontend/src/main.ts` is **byte-identical** to the committed
  `app/public/js/dexel.js` (the `.map` comparison was inconclusive by my
  method — I built to a temp path, which changes the map's relative
  sources — so I make no drift claim about the map).
- **Session accounting spot-checks that hold.** `statsLifetime` is never
  reset by `rolloverStatsIfNewDay` (`game.go`), so lifetime-delta session
  counters are correct across midnight, restarts and history
  finalisation; `subtractCounters` floors at zero; `checkSessionAutoEnd`
  runs first in `Tick` and backdates to the frozen `lastActivityAt`
  (never to `now`), and the max-duration branch clamps to the cap
  boundary; a discarded (<60 s) session consumes no log id
  (`session.go:276`) and a subsequent blank-name start deletes the stale
  `sessionNames` entry (`session.go:84-88`), so no name is inherited;
  `store.Apply`'s ordering (session → history → streak → coinsToday →
  stats) and `main.go`'s config → session-names → session-log → Apply
  sequence are respected at the only two `store.Apply` call sites
  (`main.go:1169`, `main.go:1196`).

reaching those endpoints at all.

## Suggested order of work

1. **B-1 + B-2 together** — they are one bug wearing two hats: every
   unsigned on-disk source is trusted verbatim and then re-signed. Fixing
