# dev-companion

> A cozy pixel developer who works while you work. Real typing, in any app
> on your machine, advances their sprints. Sprints pay out Dev Cash; spend
> it in the store on hoodies, chairs, keyboards, and plants for their desk.
> No meters, no hunger, no maintenance, no guilt — pure idle.

Currently shipping as a small local web app: a Go backend samples your real
activity and serves a retro NES.css frontend at `http://localhost:8080`.

---

## Quick start (macOS)

Requires Go 1.27 or newer ([go.dev/dl](https://go.dev/dl/)).

```bash
git clone git@github.com:jawwadzafar/dev-companion.git
cd dev-companion/app
go run .
```

Open **http://localhost:8080**. That's it.

- **No permission prompt.** macOS capture polls
  `CGEventSourceSecondsSinceLastEventType` — a system timestamp delta, not a
  keystroke tap — so there is no Accessibility dialog to click through.
- **Keystrokes are counted, never read.** The provider never sees which key
  was pressed, only that a keydown happened.
- Press **`S`** (or click **`[S] STORE`** in the title bar) to open the
  store modal; `S` or `Esc` closes it.

### Linux

Same commands. Real global capture reads raw `/dev/input/event*` nodes,
which needs your user in the `input` group:

```bash
sudo usermod -aG input "$USER"    # then log out and back in
```

Without that, the server still runs — it just can't see input while
another window has focus, so activity only counts while the browser tab
itself is focused, and the honesty rules in ADR 0010 freeze rather than
guess at your idle time.

### Troubleshooting

- **`ASSETS NOT FOUND` banner in the scene:** the server couldn't locate
  the repo's `assets/` directory (the sprite PNGs). This happens if you run
  the binary from somewhere other than a full checkout. Fix by setting
  `DEVCOMPANION_ASSETS_DIR=/path/to/dev-companion/assets`, or just run from
  `app/` inside the checkout as above.
- **Check what the server actually found:** `GET /api/health` returns the
  resolved `assetsDir`, whether `public/index.html` was found, and the
  build version — useful for any "it looks broken" report.

## Privacy

This is the part that has to be trustworthy, not just claimed:

- **Counts only, never content.** The activity layer records *that* a key
  was pressed and *that* the mouse moved — never which key, never any
  text, never clipboard contents.
- **App identity only, never window titles.** The frontmost-app signal is
  an app name like "Visual Studio Code" — never a window title, document
  name, or URL. (ADR 0009.)
- **100% local, no network calls.** Everything after `go run .` runs on
  your machine talking to itself over `localhost`. Nothing phones out.
- **Save file:** `~/.config/devcompanion/state.json` — Dev Cash, XP,
  current sprint index/progress, owned/equipped items and tints. No typed
  text, no titles, no timestamps of what you did — ever.
- These aren't just described here: `app/internal/activity/content_free_test.go`
  is a structural test that fails the build if anyone adds a field to the
  activity `Snapshot` type that isn't on an explicit allow-list, or whose
  name even smells like content (`title`, `text`, `clipboard`, `keycode`,
  ...).

## How it works

```
activity provider (darwin / linux)
        │  counts + booleans only
        ▼
engine (anti-mashing economy, honest moods — ADR 0005 / 0010)
        │
        ▼
WebSocket state broadcast (~1 Hz)
        │
        ▼
HTML/JS/NES.css frontend (app/public/)
```

Moods mean what they say: `Coding` requires a *recent keystroke* — mouse
motion alone never shows it. `OnBreak` only comes from genuine global
idleness; if the active provider can't see globally (e.g. no `input`-group
access on Linux), the idle clock freezes instead of guessing.

Every sprite in `assets/` is generated by committed code
(`tools/gen_assets.py`) from a fixed 18-colour palette, not hand-drawn
binaries — so any sprite is a reviewable diff, never an opaque blob.

```bash
python3 tools/gen_assets.py   # regenerates all 82 sprite/thumbnail PNGs
```

Full specs live in `docs/` (`docs/ui-spec.md`, `docs/art-direction.md`,
`docs/upgrade-design.md`); decisions and their reasoning live in
`docs/adr/`.

## Development

```bash
cd app
go test ./...
go vet ./...
go run .
```

**Scripted activity, no real input needed:**

```bash
DEVCOMPANION_FAKE_SCRIPT="type:20s,idle:40s,mouse:15s" go run . -provider fake
```

or `go run . -fake-script "type:20s,idle:40s,mouse:15s"`, which always wins
over `-provider`/the env var so a scripted demo run is never silently
overridden by a real capture path.

**Frontend dev harness:** `http://localhost:8080/?dev=1` loads a hardcoded
catalog + state client-side, for iterating on the store modal and layout
without a live backend connection.

**Headless verification:** because the frontend is plain HTML/CSS, it
renders identically on this Linux dev box and on a real Mac — there is no
"looks fine here, broken there" gap. Verify a change by running the
server, driving it with a headless browser (e.g. Playwright's Chromium)
pointed at `localhost:<port>`, and screenshotting the result; feed that
screenshot to a vision model via `scripts/visual-check.py` to check what's
actually on screen, the same way `/api/health` checks what the server
actually found on disk.

## Legacy: the Rust/Bevy implementation

`companion/` and `activity/` (the top-level Rust crates, not
`app/internal/activity/`) are the frozen Bevy implementation of these same
mechanics — kept in-tree and green as of its final commit, but not the
product. The design in the project's source PDF is native to HTML
(NES.css mockups, a store modal, retro window chrome), and building that
UI in Bevy would mean hand-rolling widgets that are a few lines of CSS in
a browser. See [`docs/adr/0011-engine-pivot-to-pdf-native-stack.md`](docs/adr/0011-engine-pivot-to-pdf-native-stack.md).

## Roadmap

Deferred, not forgotten — real items pulled from `docs/ui-spec.md` and the
pivot plan, not invented here:

- **Wails v3 wrap** — the Go server as a floating, frameless,
  always-on-top desktop window instead of a browser tab.
- **Meeting/mic detection** — a fourth activity state driven by
  `IOAudioEngineState` (noise-cancelling headphones in use), plus one
  developer frame pair and a headset overlay sprite.
- **Small idle-scene polish** — the class of touch where the character
  isn't just a static sprite (a tail-flick, a blink cycle) rather than new
  mechanics.
- **A bundled pixel font** for the frontend, beyond the current NES.css
  default.

Explicitly **not** planned: an AI-agent layer (it would need window titles
and keystroke content the privacy model forbids at the source, and a
network LLM breaks the offline-first promise), and any
Tamagotchi-style meter — energy, hunger, social battery, or death. Those
are genre-locked out, not just unscheduled.
